# Правила работы над Apex Admin

- Стек: React, TypeScript, Vite. Менеджер пакетов: npm; сохранять `package-lock.json`.
- Основной каталог и ветка `main` предназначены для интеграции. Агенты 1–3 работают только в своих worktree и ветках `agent/1`, `agent/2`, `agent/3`.
- До начала работы проверить `git status --short --branch` и свое назначение. Не изменять чужие worktree и не отменять чужие правки.
- Экраны и границы задач назначает координатор после получения HTML. Не придумывать недостающие экраны или бизнес-логику.
- Перед изменением общих файлов (`src/App.tsx`, `src/main.tsx`, `src/index.css`, конфигурация, зависимости) согласовать изменения с координатором, чтобы избежать конфликтов. Координатор может редактировать их самостоятельно.
- Стили экранов изолировать через CSS Modules или область класса компонента. Повторяющиеся части согласовывать как общие компоненты.
- Перед передачей результата выполнить `npm run lint` и `npm run build`; указать измененные файлы, результат проверок и оставшиеся вопросы. Коммитить только изменения своей задачи.

## Журнал работы — `session-log.md`

- Читать `session-log.md` только по прямому указанию пользователя. Не загружать его автоматически в начале сессии или каждой задачи.
- Дополнять журнал тоже только по прямому указанию пользователя, а не автоматически после каждого изменения. Просьба записать итог не требует перечитывать всю историю.
- По просьбе пользователя добавлять новую запись сверху, после шаблона: дата, задача, ветка и PR, что сделано, решения, затронутые файлы, результаты проверок и оставшиеся вопросы. Существующие записи сохранять; секреты и OTP в журнал не записывать.
