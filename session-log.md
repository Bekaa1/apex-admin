## 2026-10-07 — Кампании: карточка, пополнение и редактирование
Ветка: `feature/campaign-manage` · PR: https://github.com/Bekaa1/apex-admin/pull/10
Дизайн: «Apex — Мои кампании» (Claude Design), строки «Карточка кампании», «Пополнение», «Редактирование», «Список: меню «⋯»». Бэкенд — `edit_campaign`, `extend_campaign` и поля условий тарифа в `my_campaigns_stats` от 07.10, сверено только чтением.

**Что сделано**
- Кит: `ColumnsChart` (`ax-cols`), `Delta` (`ax-delta`), `Menu` (`ax-menu`) и иконки `trending-down`, `more`, `pause` перенесены из CSS холста в `src/design-system`.
- Карточка `/cabinet/campaigns/:id`:
  - шапка с действиями по стадии и меню «⋯»;
  - блок «что происходит» (проверка, проверка изменений, ждёт оплаты, отклонена, нет бюджета);
  - статистика за 30 дней с дельтой и графиком по дням, у завершённой — итоги по неделям;
  - ролик и описание, магазины и зоны, бюджет с «хватит примерно на N дней», история.
- Пополнение `/cabinet/campaigns/:id/topup` → `extend_campaign`, экран «Счёт выставлен» `/topup/sent`:
  - сумма с быстрыми суммами от минимума тарифа;
  - если условия тарифа изменились с прошлого счёта — блок с обязательной галочкой согласия;
  - ошибки: сумма — у поля, `tariff_changed` перечитывает условия, `missing_email` ведёт в профиль.
- Редактирование `/cabinet/campaigns/:id/edit` (туда же «Исправить») → `edit_campaign`:
  - мастер в режиме `edit`: тариф пропущен («Не меняется»), последний шаг — «Проверка изменений» с «было → стало», бюджет только для чтения;
  - без изменений отправить нельзя;
  - экран «Изменения отправлены на проверку».
- Список: стадия «Проверяем изменения» (`pending` у запущенной кампании) и меню «⋯» (Статистика, Редактировать, Пополнить, Повторить кампанию). «Пополнить» на главной ведёт на экран пополнения.

**Решения**
- Тариф при редактировании не меняется: бэкенд отвечает `tariff_change_not_allowed`, пользователь решил следовать бэкенду. Закрывает вопрос из записи P1.
- При продлении сверяем минимум пополнения, цену показа на экране не показываем (так нарисовано по просьбе пользователя). Пока в счёте нет минимума, блок «условия изменились» включается по смене `tariff_version`, без значения «было».
- «Исправить» идёт через `edit_campaign` (`resubmit_campaign` — его алиас); `resubmitCampaign` удалён.
- Пауза рекламодателем (нарисована сверх ТЗ) отложена.
- «Изменения на проверке» определяем по `status = pending` и заполненной `start_date`.
- Всё — одним PR по просьбе пользователя.

## 2026-10-07 — Регистрация: обязательные email и телефон с OTP
Ветка: `fix/phone-email-required` → `main` · PR: https://github.com/Bekaa1/apex-admin/pull/8 · Squash-коммит: `dc7a5f4`
- Что сделано:
  - Вместо общего поля контакта добавлены отдельные обязательные поля email и телефона. Сохранены проверка пароля, согласие с документами и нормализация казахстанских номеров с `7`, `8` или без кода страны.
  - Порядок регистрации: email, телефон и пароль → подтверждение почты кодом → отправка и подтверждение SMS → данные компании. Оба контакта привязываются к одному аккаунту Supabase Auth.

  - Добавлены отдельные сообщения о занятой почте и номере, переход к восстановлению пароля, обработка лимитов и ошибок, блокировка повторных запросов во время отправки и проверки.
  - Для новых регистраций интерфейс возвращает пользователя к подтверждению контактов при попытке открыть кабинет или данные компании раньше времени. Перед сохранением данных компании повторно запрашивается пользователь через `auth.getUser`.
  - Обновлены тексты на русском, казахском и английском; вход существующих аккаунтов с одним контактом сохранён.
- Решения: аккаунт создаётся по email, телефон подтверждается в той же сессии. ### Бизнес-логика
1. **Запуск.** Показы начинаются (`status = active`), только когда модератор одобрил ролик И бюджет оплачен. Порядок любой: оплатить можно, пока идёт проверка.
2. **Статусы:**
   - `pending` — на проверке;
   - `rejected` — модератор вернул кампанию с причинами; рекламодатель исправляет и отправляет снова → `pending`;
   - `awaiting_payment` (новый) — одобрена, ждёт оплаты;
   - `active` — идут показы;
   - `budget_ended` — бюджет закончился; после пополнения → `active`;
   - `completed` — завершена.
3. **Тарифы** (в скобках — минимальный бюджет):
   - **Стандарт** (500 000 ₸) — ролик в общей ротации на всех тележках выбранных магазинов;
   - **Стандарт + Зоны** (1 000 000 ₸) — то же плюс приоритет у выбранных полок (зон);
   - **Премиум** (2 000 000 ₸) — плюс больше показов в ротации;
   - **Корпоративный** — по договорённости, только через заявку менеджеру; эксклюзив бренда в зоне.
4. **Деньги.**
   - Бюджет кампании оплачивается по счёту, счёт приходит на почту при отправке.
   - Показы списываются из бюджета по цене показа тарифа.
   - Когда бюджет закончился, показы останавливаются; пополнение — это новый счёт.
5. **Модерация.**
   - 6 правил с кодами: `duration_7s`, `languages_kk_ru`, `prohibited`, `claims`, `flashing`, `metadata`.
   - При отклонении сохраняются коды нарушенных правил и комментарий.
   - Срок — до 24 часов в рабочие дни, результат приходит письмом.
6. **Черновиков нет.** Кампания появляется в базе только при отправке.
