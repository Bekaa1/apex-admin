# PDF-отчёт статистики с рекомендациями ИИ

## Пользовательский сценарий

На `/cabinet/stats` кнопка «Скачать отчёт PDF» использует выбранную кампанию, период и состав кампаний. Доступны ru/kk/en. При отсутствии показов, загрузке статистики или в демонстрационном режиме выгрузка недоступна. Ошибка данных, анализа или PDF не подменяется пустым документом.

PDF содержит дату формирования в Asia/Almaty, выбранный период, основные показатели, таблицу кампаний, краткий итог и рекомендации ИИ. Текст доступен для выделения; шрифт Onest встроен в PDF. Длинные названия переносятся; таблица повторяет заголовок на следующих страницах.

## Сервер и авторизация

- `POST /api/stats/report` обрабатывается существующим Node-сервисом `server/chat/server.ts`; реализация находится в `server/stats/`.
- Браузер передаёт только `{ campaignId, period, scope, language }` и действующий Bearer JWT **Apex**. Готовые показатели, произвольный user_id и токен анонимного Chat не принимаются как источник прав.
- Сервер проверяет пользователя через Apex `auth.getUser`, затем использует отдельный клиент на время запроса: публичный ключ Apex + JWT вызывающего пользователя. Auth-сессия сервера не сохраняется.
- Источники: `my_campaigns_stats` и `my_daily_plays_by_campaign`, с сохранением RLS пользователя. Привилегированный ключ для отчётов не используется. Записей в БД нет.
- Стабильные запросы страниц с exact count предотвращают выгрузку заведомо усечённого ответа. Изменение count между страницами приводит к ошибке и ручному повтору. Несколько запросов не являются транзакционным снимком БД: при параллельном обновлении показатели могут отличаться от уже открытой страницы.
- Лимиты: до 200 выбранных кампаний, до 5000 доступных строк кампаний при выборе и до 100000 строк дневной статистики. Превышение сообщает о необходимости сузить выбор, без частичного PDF.
- Один отчёт на пользователя одновременно, максимум два на процесс и три попытки на пользователя за пять минут. Лимиты хранятся в памяти процесса; при горизонтальном масштабировании нужен общий лимитер.
- Тайм-аут OpenRouter — 50 секунд, операции сервера — 90 секунд. Автоматических повторов анализа нет. Закрытие страницы/смена фильтров отменяют старый запрос. Повторный клик блокируется синхронно и в UI.
- PDF формируется в памяти, отдаётся с `private, no-store` и не сохраняется на сервере. Логи содержат только безопасные коды ошибок, без токенов и статистики.

## Значение показателей и ИИ

Границы периода и выбор запущенных кампаний вынесены в общий `reportSelection.ts`. Расчёты сопоставлены с существующей страницей для 36 комбинаций фильтров.

- За отдельный период расход рассчитывается как показы × текущая цена кампании; в PDF он явно обозначен расчётным. Это не историческое списание при изменении тарифа.
- За всё время расход берётся из `spent_budget`. Неизвестные значения не заменяются нулём.
- Текущий день может быть неполным. Нет подтверждённых данных о продажах, конверсиях, уникальном охвате, эффективности креатива и распределении показов по часам, зонам и супермаркетам. Такие выводы не добавляются в отчёт.
- OpenRouter получает только показатели, периоды, статусы, даты старта и анонимные ссылки C1/C2. Названия кампаний, UUID, контакты, медиа и JWT не отправляются.
- Модель выбирает значимые наблюдения из серверного набора и предлагает действия и способ проверки результата. Точные числа, итог и основания рекомендаций строятся сервером из фактов. Ответ проверяется по JSON-схеме и допустимым ссылкам; произвольные числовые утверждения модели отклоняются.
- Рекомендации остаются гипотезами. Проверка структуры не доказывает правильность каждого совета ИИ; неподтверждённые выводы нельзя использовать как финансовую гарантию.
- При недоступном OpenRouter или невалидном ответе PDF не выдаётся; пользователь получает сообщение с возможностью ручного повтора.

## Конфигурация и развёртывание

Только серверные переменные (без префикса VITE):

```env
APEX_PUBLIC_SUPABASE_URL=
APEX_PUBLIC_SUPABASE_KEY=
OPENROUTER_API_KEY=
STATS_REPORT_MODEL=
```

Публичный ключ Apex должен соответствовать основному проекту, не Chat. `STATS_REPORT_MODEL` переопределяет модель; иначе используется `OPENROUTER_MODEL` существующего сервиса, затем `google/gemini-2.5-flash-lite`. Модель должна поддерживать structured output. Значения ключей не хранить в Git.

Для локального запуска используются существующие `npm run dev:chat` и `npm run dev:public`. Vite проксирует `/api/stats/report` на порт 8787. Допустимые Origin задаются существующей `CHAT_ALLOWED_ORIGINS`; при другом локальном порте его необходимо добавить.

При публикации необходимо обновить **серверный контейнер и публичную сборку**. Dockerfile включает сервер отчётов, общую функцию периодов и Onest с лицензией. `deploy/chat/stats-report.caddy` содержит правило проксирования; его нужно включить в сайт apexmedia.kz перед SPA fallback. Сборки фронтенда без этого endpoint недостаточно. Административная сборка кнопку отчёта не включает.

Добавлены серверная зависимость `pdfkit` и типы `@types/pdfkit`; версии существующих зависимостей не обновлялись. PDFKit и серверный OpenRouter-код не входят в клиентский bundle.
